# AI Agent Guidelines & Senior Engineering Standards

> Global baseline generated by Aethries/dotfiles ai-skills. Load specialized domain skills only when the task needs them.

## 1. Operating modes
- Simple question, explanation, or docs-only task: answer or inspect without forcing a coding workflow.
- Source change, bug fix, refactor, or architecture work: use `repo-first-implementation` and `agent-memory-bootstrap`.
- Domain-specific work: load only the relevant project skill after the repository context is known.

## 2. Repository-first sequence
1. Read applicable `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, README, manifests, lockfiles, and CI.
2. Run `detect-stack` when stack context is missing or stale.
3. Query CodeGraph/Codebase Memory before tracing unfamiliar symbols or dependencies.
4. Inspect at least two neighboring implementations and record naming, placement, exports, errors, and tests.
5. State the input/output/error/side-effect contract and smallest complete file set.
6. Preserve project conventions and dependency direction. Apply SOLID diagnostically; do not invent layers.
7. Make a minimal coherent diff. No unrelated cleanup, renaming, or dependency additions.
8. Update the graph, run focused checks, then applicable lint/format/typecheck/test/build gates.
9. Review the final diff and report passed, failed, blocked, and not-run checks separately.

## 4. Memory protocol
- If an Agent Memory MCP is configured, recall only project/task-relevant decisions, conventions, failures, and handoffs before editing.
- If unavailable, use existing repo-owned memory, specs, plans, and ADRs; do not invent a memory directory without evidence.
- Store only durable, verified facts. Never store secrets, credentials, raw source, full transcripts, speculative guesses, or noisy command output.
- Repository behavior and explicit user requirements outrank stale memory. Mark superseded decisions instead of duplicating them.
- Memory retrieval is context, not proof. Source inspection and verification remain mandatory.

## 5. Efficiency and safety
- `ponytail`: smallest working diff; reuse existing abstractions before adding code.
- `rtk`: filter noisy terminal output when available.
- `security-guardrails`: no hardcoded secrets; validate inputs and authorization boundaries.
- Stop and ask when conventions conflict, scope is unclear, or a new dependency/layer/public contract is required.
