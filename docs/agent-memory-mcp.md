# agentmemory.dev integration

Status: repository integration complete; activation requires
`./scripts/build.sh switch`.

## Scope

This repository uses the official [`agentmemory.dev`](https://www.agent-memory.dev/)
packages:

- Full runtime: `@agentmemory/agentmemory@0.9.29`.
- MCP shim: `@agentmemory/mcp@0.9.29`.
- Engine: `iii` v0.11.2, packaged as `pkgs/iii-engine.nix`.

NixOS starts the full runtime as `agentmemory.service`. It binds only to
loopback and uses REST/MCP port 3111, viewer port 3113, streams port 3112, and
iii port 49134. Mutable state is outside Git at `/var/lib/agentmemory`; the
repository contains only secret-free configuration and policy.

The first start may download the pinned npm package and its dependencies into
the primary user's npm cache. Subsequent starts reuse that cache. The system
service supplies the pinned iii binary through `PATH`, so the upstream CLI does
not need to download a second engine.

## Agent wiring

The same official stdio MCP shim is repository-owned for every current agent:

| Agent | Repository source | Live target after sync |
| --- | --- | --- |
| Codex CLI/Desktop | `resources/codex/config.toml` | `~/.codex/config.toml` |
| Antigravity CLI | `resources/gemini/mcp_config.json` | `~/.gemini/config/mcp_config.json` |
| Antigravity IDE | `resources/gemini/mcp_config.json` | `~/.gemini/antigravity/mcp_config.json` |
| Claude Code | `.mcp.json` | project-scoped Claude MCP config |

Global skill links and instruction files for all four adapters continue to be
generated by `scripts/sync-editors.sh` and `scripts/ai-skills.sh`. The
repository-owned `agent-memory-bootstrap` skill is the workflow contract: live
memory is useful context, but source, tests, and explicit task requirements
remain authoritative.

## Activation and verification

```sh
./scripts/build.sh switch
./scripts/sync-editors.sh --replace

systemctl is-enabled agentmemory.service
systemctl is-active agentmemory.service
curl -fsS http://127.0.0.1:3111/agentmemory/health
curl -fsS http://127.0.0.1:3111/agentmemory/livez
codex mcp get agentmemory
claude mcp get agentmemory
jq '.mcpServers.agentmemory' resources/gemini/mcp_config.json
```

The `--replace` flag is only needed when an existing global rule file is an
unmanaged regular file. The sync script now updates an empty placeholder file;
non-empty unmanaged files remain protected unless explicitly replaced or
backed up.

## Memory hygiene and Vault sync

Store only durable, verified project decisions, conventions, failure lessons,
and handoff state in reviewed Markdown under `resources/agent-memory/` or the
repository's existing documentation locations. Never store credentials, private
keys, raw source files, full transcripts, speculative guesses, or noisy output.

Git synchronises the reviewed layer: agent configuration, the
`agent-memory-bootstrap` workflow, and durable Markdown decisions. The mutable
database and user-level agentmemory settings are kept out of Git and can be
carried in the local encrypted Vault:

```sh
# Stop the service first; the command refuses a live process to avoid a partial
# SQLite/WAL or iii state snapshot.
sudo systemctl stop agentmemory.service
AGENTMEMORY_DATA_DIR=/var/lib/agentmemory \
  ./scripts/vault.sh backup --scope agentmemory

# On a target machine, restore while the service is stopped, then start it.
AGENTMEMORY_DATA_DIR=/var/lib/agentmemory \
  ./scripts/vault.sh restore --scope agentmemory
sudo systemctl start agentmemory.service
```

The default encrypted file is `secrets.agentmemory.vault`, which is ignored by
Git. It contains the state directory and `~/.agentmemory` settings (including a
private `.env` when present), while runtime caches, logs, PIDs, sockets, and
downloaded binaries are excluded. `config.env`, MCP wiring, skills, and
reviewed Markdown remain secret-free repository files. This is a local/manual
encrypted backup boundary, not automatic cloud or Vault-server synchronisation;
no rclone or remote secret backend is invoked.
